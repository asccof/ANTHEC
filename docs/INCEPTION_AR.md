# ANTHEEC — تقرير بدء التطوير الهندسي

الإصدار 0.1 — 10 أكتوبر 2026 — الحالة: أساس هندسي محلي، ليس تطبيقًا جاهزًا.

## ما أُنجز فعليًا

فُحصت المرفقات السبعة: مواصفات Word بنسختيها، نسخة PDF، تصميم Word وPDF، الملف التعريفي، والنموذج HTML. استُخرجت الفقرات والجداول من Word والنص من PDF وفُحص HTML مباشرة. نسختا المواصفات Word متطابقتان بايتًا وفق SHA-256. نسخ PDF وWord متوافقة في المتطلبات الأساسية التي جرت مقارنتها؛ لا يُدّعى التطابق البصري أو الحرفي. استخراج النص العربي من الملف التعريفي يشوّه بعض الأحرف والأرقام، لذلك لا يعتمد لتثبيت بيانات الاتصال أو أرقام الاستمارة.

أُنشئ مستودع Git محلي مستقل، جرد بالمصادر وبصماتها، مصفوفة متطلبات مرتبطة بمعايير قبول، سجل قرارات، وخطة مهام ذات تبعيات وبوابات. أُضيف مدقق آلي لاتساق خط الأساس واختبارات سلبية له، وسير CI جاهز للتشغيل بعد توفير المستودع البعيد.

بحث GitHub عن ANTHEEC في المستودعات المتاحة أعاد صفر نتائج. هذا لا يثبت عدم وجود مستودع خاص خارج الصلاحيات. لم يُنشأ Issue أو PR ولم تُنفذ مراجعة Codex خارجية. لا يوجد تطبيق Django أو قاعدة PostgreSQL أو CMS أو PDF مولد حتى الآن. حزم Django وWagtail وpsycopg غير مثبتة في البيئة الحالية؛ لا يعني هذا أنها غير قابلة للتثبيت لاحقًا.

## ترتيب المرجعيات

تعليماتك الحالية هي حدود التنفيذ الملزمة. يليها دفتر التحملات التنفيذي v1.0، ثم التصميم DDD-001 بوصفه اقتراحًا هندسيًا، ثم الملف التعريفي للمحتوى المؤسسي. النموذج التفاعلي دليل لمسارات العرض فقط. التعارضات لا تتحول تلقائيًا إلى قواعد إنتاجية. ANTHEEC الاسم المعتمد بالفعل؛ لا نطلب إعادة اعتماده. لا تُنقل حوكمة أو قواعد أو بيانات MHIOS إلى هذا المشروع.

## بنية مقترحة قابلة لإثبات الجدوى

تطبيق واحد بوحدات داخلية مستقلة: الهوية والصلاحيات، المحتوى والترجمة، العضويات، الاعتماد، المالية، الأنشطة، الشراكات والفروع، الوثائق، الإشعارات، والتدقيق. هذا يقلل إدارة خدمات متعددة في البداية، ويسمح بفصل عامل توليد الملفات والإرسال عند الحاجة.

Django + PostgreSQL + Wagtail هي فرضية إثبات الجدوى الواردة أصلًا في التنفيذي §11، وليست قرارًا تقنيًا نهائيًا. واجهات مولدة على الخادم، دون فرض تطبيق JavaScript منفصل. اختبار Wagtail يجب أن يثبت التحرير بالمقاطع، ثلاث لغات، المعاينة، النسخ والاستعادة، والجدولة؛ دعم الترجمة التلقائية يحتاج طبقة مستقلة ولا يُفترض توفره تلقائيًا. اختيار الإصدارات والقفل يتم بعد التحقق من وثائق الدعم والتوافق الرسمية في مهمة PoC.

علاقات رئيسية: شخص ← طلب عضوية ← قرار ← عضوية ← وثيقة؛ ملف اعتماد ← قرار ← اعتماد ← وثيقة؛ نشاط ← تسجيل ← دعوة وحضور؛ محتوى ← نسخ لغوية ← مراجعات؛ جهة ← شراكة واتفاقية. للفرد والمؤسسة والدورة هويات مرجعية صريحة، وليس applicant_id متعدد المعاني بلا قيود. السجلات المالية والقرارات لا تُحذف عبر CRUD عادي.

كل إجراء حساس: تحقق جلسة وMFA وصلاحية وسجل، ثم transaction مع قفل عند التنافس، ثم قرار وأثر تدقيق وoutbox. تُنشأ الوثيقة بمرجع فريد وتُعرض pending_generation حتى اكتمال الملف. فشل البريد لا يعيد القرار أو الرقم. صفحة QR لا تعتمد cache يخفي السحب الفوري. حفظ token_hash مع إدارة آمنة للرابط عند التسليم، ومنع تسجيل الرموز في سجلات الطلبات.

تخزين المرفقات خاص، والتنزيل عبر تحقق صلاحية أو رابط قصير الأجل. حدود MIME والحجم وفحص الملفات وعزل SVG/HTML والمحتوى النشط. تنظيف HTML والتحقق من CSRF/XSS، حماية النماذج والتحقق من التخمين، MFA للإدارة، عدم تسجيل الهوية الوطنية أو الرموز أو المرفقات في logs. التدقيق إضافة فقط على مستوى التطبيق وصلاحيات DB؛ لا يُدّعى أنه غير قابل لتعديل مسؤول قاعدة البيانات. توثيق إجراء تصحيح يحتفظ بالأثر.

البريد والترجمة بواجهات قابلة للتبديل؛ في التطوير adapters وهمية وحوض بريد محلي لا يرسل خارجيًا. لا نصوص إدارية حساسة تُرسل للترجمة. لا تُستخدم ملفات الأعضاء كأمثلة أو سياق لمهام Codex. تراخيص كل مكون تُفحص قبل تثبيته؛ لا يُعيَّن مزود استضافة أو خدمات مدفوعة الآن.

## أسلوب GitHub وCodex والمراجعة

لكل مهمة Issue بنطاق واستثناءات وتبعيات وAC، فرع محدود، ثم PR يبين السلوك والاختبارات وقرارات ADR المتأثرة. قراءة HEAD والوثائق والتعليمات قبل التعديل، عدم الدفع مباشرةً إلى main، وعدم دمج تغيير تفشل اختباراتُه أو عليه ملاحظة حاسمة. فحوص migration وPostgreSQL والصلاحيات والأمن وi18n ضمن CI بعد النواة. كل مراجعة مرتبطة بآخر SHA؛ تغيير الكود بعدها يستوجب إعادة الفحوص المتأثرة. مراجعة Codex تُطلب عند توفر واجهتها في المستودع؛ لا تُعتبر متاحة أو ناجحة لمجرد وجود أدوات GitHub. إذا لم تتوفر، تُسجل مراجعة ذاتية ومراجعة بشرية منفصلتين ولا تسمى مراجعة Codex.

## قرارات تحتاج موافقتك

1. تأكيد الفصل الصريح لشهادة الاعتماد عن امتياز العضوية، واعتماد اسم المستوى الثالث الذي لا يوحي باعتماد تلقائي (F02/F03). هذا يحسم صياغة مؤسسة قديمة دون تغيير الملف الأصلي.
2. سياسة سنة الصلاحية والتجديد المبكر وتاريخ البداية و29 فبراير (F06)، ومدة العرض وسعر التجديد (F04)، قبل تطوير حسابات الصلاحية والمالية.
3. الجهات المخولة بالموافقة والسحب والتحقق المالي، والحقول العامة في الدليل وصفحة التحقق (F09/F10)، قبل تشغيل الصلاحيات والبيانات الحقيقية.
4. سياسة بيانات الطلبات والاحتفاظ والحذف واشتراط حساب للضيف وأهلية القاصرين، قبل استقبال طلبات حقيقية. الخدمة المؤسسية العامة لا تعني تفعيل ملفات سريرية.

تحديد رابط مستودع ANTHEEC أو إنشاء مستودع مستقل وإتاحته مطلوب للخطوة البعيدة فقط، وليس شرطًا لمواصلة PoC محلي. لا توجد مدة أو تكلفة أو نسبة إنجاز للمشروع الكامل يمكن تثبيتها قبل إثبات التقنية وحسم السياسات. المنجز الآن هو ENG-001؛ الباقي مهام محددة أعلاه.
