# دليل الاستعادة والأمان — ANTHEC

إعداد 15 أكتوبر 2026. هذا إجراء جاهز للمراجعة والتنفيذ المنضبط؛ **لم تنفذ استعادة فعلية لاستضافة Render**. لا ترخيص إطلاق أو إنفاق، ولا إعادة ضبط MFA أو تغيير مفتاح تشفير أو اتصال قاعدة تلقائيًا.

وثائق Render الرسمية التي روجعت في 2026-10-15: [Postgres Recovery and Backups](https://render.com/docs/postgresql-backups). نافذة PITR تعتمد على خطة **المساحة** (Hobby ثلاثة أيام، Pro أو أعلى سبعة)، وتُحفظ الصادرات المنطقية سبعة أيام. إنشاء PITR ينشئ قاعدة جديدة. هذه قدرات موثقة وليست إثباتًا لوجود نقطة استعادة صالحة لحسابنا؛ افحص صفحة Recovery الفعلية وسجل النافذة/آخر تصدير قبل الاعتماد عليها. لا تضغط Start Recovery قبل اعتماد التكلفة والهدف. لا تستخدم أوامر الحذف/التنظيف في أمثلة المزود.

## 1. فحص حي للقراءة فقط

بعد نشر أمر هذه الحزمة ومطابقة الالتزام، في **Shell خدمة ANTHEC المذكورة فقط**:

```sh
python manage.py check_owner_readiness
```

يعرض JSON ثابت البنية بمؤشرات فقط، دون اسم مستخدم أو بريد أو كلمة مرور أو مفتاح أو OTP. يشترط وضع owner-testing ويستخدم معاملة PostgreSQL للقراءة فقط. يفحص وجود رئيس نشط واحد، كلمة مرور قابلة للاستعمال، جهاز TOTP مؤكد ورمز استعادة غير مستعمل، وتركيب الحاجز وإعدادات HTTPS/الكوكيز والبريد والوسائط. لا يصلح شيئًا ولا يستهلك رمز استعادة ولا يولد وثيقة. خروج الأمر بنجاح يعني إتمام الرصد فقط؛ **راجع قيم true/false** ولا تعتبره إقرار جاهزية. false في أي بند يحتاج تفسيرًا وتصحيحًا معتمدًا قبل القبول. أخطاء القاعدة تُحجب برسالة عامة؛ لا تطبع رابط الاتصال بحثًا عن السبب.

وجود رمز استعادة في القاعدة لا يثبت أنك تملك نسخته الأصلية. ولا يثبت هذا الأمر حفظ مفاتيح خارج الخادم أو فك تشفير قاعدة مستعادة أو قدرة التحمل. إن بقي `release_authorized: false` فذلك مقصود دائمًا.

## 2. حفظ المفاتيح قبل أي استعادة

| المادة | مسؤولية المالك والتحقق المطلوب دون كشف المحتوى |
|---|---|
| `ANTHEEC_DATA_KEY` | الاحتفاظ بالمفتاح الأصلي في مخزن أسرار خاص مع نسخة استرجاع محمية منفصلة. يثبت اختبار على نسخة مستعادة أنه المفتاح الصحيح. لا تستبدله بمفتاح جديد: ذلك لا يفك البيانات القديمة. |
| `ANTHEC_BACKUP_KEY` | مفتاح مستقل لتغليف الصادرات، منفصل تشفيريًا عن مفتاح البيانات وعن ملفات النسخ؛ أداة التغليف ترفض التطابق. لا يلزم وضعه في خدمة الويب. |
| `ANTHEEC_SECRET_KEY` | حفظه بشكل آمن؛ تغييره قد يبطل الجلسات ولا يستعيد مفتاح البيانات. |
| الوصول الإداري | كلمة مرور خاصة، جهاز Authenticator بتوقيت تلقائي، ورموز الاستعادة الأصلية في مخزن خاص. لا صور QR أو أسرار TOTP في التذاكر أو المحادثة. |
| اتصال القاعدة | يبقى داخل مدير الأسرار/Render؛ لا URL في سطر أوامر مسجل أو ملف مستودع أو محضر قبول. |

يسجل المحضر **تاريخ تحقق الحفظ ومكانه العام والمسؤول فقط**، لا السر ولا بصمته. لا تدوير تجريبي لمفتاح البيانات على الخدمة: إعادة تشفير البيانات والأصول التاريخية ليست آلية معتمدة حاليًا، وتحتاج حزمة مستقلة ونسخة احتياطية واستعادة مثبتة وخطة رجوع.

## 3. تصدير ونسخة خارج المزود

لم تُختَر بعد وجهة التخزين أو سياسة الاحتفاظ أو تواتر النسخ أو أهداف RPO/RTO؛ يحددها المالك مع المراجعة القانونية والأمنية، ولا نخترع مدة قانونية. لا cron أو تخزين مدفوع جديد في هذه الحزمة.

1. تحقق من هوية القاعدة وصفحة Recovery دون بدء استعادة. سجل توفر النافذة وأوقات الصادرات فقط. تنزيل تصدير ANTHEC إلى محطة خاصة مشفرة لا يتطلب فتح قاعدة البيانات خارجيًا. لا تنزل بياناتها إلى المحادثة أو المستودع.
2. حدد صيغة التصدير: تصدير Render هو `.dir.tar.gz`؛ أرشيف `pg_dump --format=custom` صيغة مختلفة. أداة `encrypt_backup.py` تغلف أي ملف ضمن الحد، لكنها **لا تحول صيغة PostgreSQL**. لا تمرر أرشيف Render المضغوط مباشرة إلى `pg_restore` كأنه custom.
3. على محطة المالك المشفرة فقط، بحقوق ملفات مقيدة، احقن المفتاحين من مدير الأسرار دون طباعتهما أو كتابتهما في سجل الطرفية. استعمل الأداة القائمة للتغليف ثم لفك نسخة اختبارية إلى اسم جديد:

```sh
python tools/encrypt_backup.py encrypt /private/anthec/source-export /private/anthec/export.fernet
python tools/encrypt_backup.py decrypt /private/anthec/export.fernet /private/anthec/recovered-export
```

المسارات أمثلة يجب استبدالها بمجلد خاص موجود. الأداة لا تكتب فوق ملف موجود، وتستخدم 0600، وحدها 128 MiB من الملف غير المغلف؛ ليست أداة streaming أو اختبار ذاكرة 512 MiB. لا تشغلها على خادم الويب الصغير. لا تخزن الملف الأصلي أو المفاتيح على قرص خدمة مؤقتة أو في ChatGPT. تحقق من تطابق الملفين وفك التغليف محليًا؛ سجل النتيجة فقط. تنظيف النسخة المكشوفة حسب سياسة المحطة المشفرة لا يساوي ضمان محو آمن على SSD.
4. اختبر فساد نسخة **مكررة اصطناعية** وفشل مفتاح غير صحيح؛ لا تعدل النسخة الوحيدة أو مفاتيح الخدمة. CI يغطي رفض العبث/المفاتيح غير الملائمة، لكن حيازة نسخة المالك تحتاج إثباتها مستقلة.

## 4. تمرين الاستعادة

المسار المجاني المثبت حاليًا هو CI القابل للتخلص منه: `tools/validate_recovery.py` مقيد بـ`CI=true` و`PGDATABASE=antheec_test`، يعيد إلى `antheec_restore_test` ويفحص قيمة اصطناعية مشفرة. **لا تشغله في Render Shell ولا تغيّر أسماء قواعد الاستضافة لإقناعه بالعمل.**

تمرين الاستضافة الفعلي مخطط ولم ينفذ. لا ننشئ قاعدة مدفوعة أو قاعدة منطقية إضافية على المثيل الصغير أو نغير الاتصال الحالي لتنفيذه. قبل التنفيذ يجهز المهندس عرضًا محددًا للهدف والتكلفة ومدة الاحتفاظ وخطة الرجوع؛ يبدأ الإنشاء المدفوع بعد موافقة المالك فقط. البديل: استعادة تصدير حقيقي إلى PostgreSQL 16 محلي خاص، بعد ضبط الحماية والأسرار؛ قد يثبت صلاحية التصدير والمفتاح لكنه لا يثبت PITR أو الاستعادة داخل Render.

معايير التمرين عند توفير الهدف المعزول:

| المرحلة | معيار النجاح والأثر المسموح |
|---|---|
| تحديد الهدف | قاعدة جديدة فارغة منفصلة، مصدرها واسمها واضحان؛ لا الأصل ولا Tighri. لا drop/clean، ولا cutover في تمرين تحقق. |
| الاستعادة | أدوات PostgreSQL 16، صيغة صحيحة، دون owner/ACL غير مناسبين، توقف عند أول خطأ. لا نسخ مفاتيح إلى سجل الأوامر. |
| اكتمال البيانات | مقارنة أعداد السجلات والمراجع/الإصدارات/الحالات على نقطة التصدير نفسها، ومخطط migrations؛ لا أسماء أو محتويات في المحضر. |
| التشفير | بالمفتاح الأصلي: تحقق من قراءة بيانات خاصة وعينة صورة وأصل وثيقة وأثر تدقيق مشفر **موجودين فعليًا**. العينة غير الموجودة تسجل «غير منطبق/لم يثبت»، ولا تُصدر وثائق على الأصل لملء الاختبار. |
| الملفات | فك وثيقة موجودة والتحقق من تطابق بايتاتها/سلامتها وصلاحيات الوصول؛ لا تعد توليدها بدل إثبات حفظ الأصل. |
| التشغيل المعزول | لا بريد أو دفع أو نشر خارجي أو معالجة outbox تلقائية. السماح بالدخول للمختبر فقط، والتحقق من MFA/الصلاحيات/الخصوصية. |
| الزمن والقرار | سجل أوقات بداية/نهاية التصدير والاستعادة والتحقق، والفجوة الفعلية للبيانات؛ قارنها بـRPO/RTO بعد اعتمادهما، لا تعد بنجاح غير مقاس. |
| الإنهاء | الأصل يبقى عاملًا ولم يتغير اتصاله؛ مصير الهدف والتصدير والمفاتيح وفق قرار موثق. لا حذف الأصل ضمن التمرين. |

## 5. استرجاع الدخول الإداري

تحقق أولًا، دون مشاركة السر، من وجود كلمة المرور وجهاز المصادقة ورموز الاستعادة لديك. اختبر استعمال رمز احتياطي وإعادة استعماله **في الحساب الاصطناعي بالبيئة المعزولة فقط**: الاستعمال الأول مع كلمة المرور ينجح، والثاني يرفض ويسجل الأثر. اختبارات `governance.tests.PolicyTests` تغطي ذلك، ولا تعني أنك تملك رموز حسابك الحالي.

لا تستهلك رمز الحساب الحالي لإثبات التجربة، ولا تحذف جهاز TOTP المؤكد. إذا فُقدت كل العوامل، أوقف المحاولات المتكررة؛ يلزم إجراء استرداد هوية منفصل موثق وفق POL-04، ولا يكفي امتلاك Django superuser لتغيير الرئيس. لا مسار تلقائي معتمد لنقل الرئيس أو تجاوز العامل الثاني.

## 6. محضر الأمان والاستعادة

لكل بند: الحالة **مثبت / فشل / لم ينفذ / محجوب**، وقت UTC، نسخة المصدر، المرجع التقني المنزوع من الأسرار، المنفذ، والقرار التالي. البنود الحالية المفتوحة: نتيجة الفحص داخل الخادم؛ حيازة المفاتيح والرموز؛ نسخة خارج المزود؛ استعادة فعلية وفك أصولها؛ RPO/RTO؛ اختبار التحمل على 512 MiB؛ حماية الفرع الفعلية؛ مراجعة حقوق/احتفاظ/CNDP/استضافة/قاصرين مستقلة. لا يحول نجاح الأداة أو CI أي بند منها تلقائيًا إلى «مثبت».

الجاهزية الهندسية لا تعتمد المحتوى القانوني ولا تطلق التسجيل أو المدفوعات أو الإصدار. يبقى [سجل الجاهزية](RELEASE_READINESS_REVIEW.md) مرجع القرار، و[حزمة قبول المالك](OWNER_ACCEPTANCE_AR.md) مرجع السيناريوهات.
