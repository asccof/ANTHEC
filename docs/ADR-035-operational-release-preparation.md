# ADR035 — Secure operational runtime preparation

Date: 2026-10-21. Owner directs engineering toward full launch and explicitly defers CNDP filing. Deferral is not an exemption, legal acceptance or evidence that a formal obligation was discharged. Do not publish private signed policy/source attachments in this public repository.

## Bounded decision

Prepare `ANTHEEC_MODE=operational` in the secure hosted settings. Deployment alone leaves the existing Docker default `owner-testing` unchanged. Operational startup needs exactly `ANTHEEC_OPERATIONAL_RELEASE_APPROVED=1` and `ANTHEEC_PUBLIC_CONTENT_APPROVED=1`. These operator acknowledgements are not automatic certification of legal/security/recovery acceptance; do not set them on Render during this preparation.

Operational mode keeps DEBUG off, exact HTTPS origin, encrypted DB-backed private assets, disabled filesystem uploads, dummy outbound email, dedicated ANTHEC PostgreSQL namespace, secure cookies, unchanged primary MFA at login and independently scoped delegates. Application, manual payment/refund and document issuance switches each default to `0`; only literal `0` and `1` are accepted. Both preview modes still reject any nonzero switch. `development`/static-build settings cannot be substituted for the operational runtime. No online payment gateway or outbound mail provider is introduced.

Existing public and member views resume their own ownership/publication checks in operational mode. The private preview primary-only perimeter is deliberately absent; administrative view guards, delegation epochs and primary MFA remain. A password-only primary session renders public editorial reads anonymously and redirects private paths to the login factor; the stored session is preserved. This closes the same CMS login-restriction/personalization gap previously addressed for editorial preview. The global admin login budget is reused after CSRF validation, without trusting forwarding headers. Responses remain no-store and noindex during initial operational release; search indexing is not inferred from the instruction to complete functionality.

`python manage.py check_release_readiness` observes all secure hosted modes under a PostgreSQL read-only transaction. It returns booleans for primary account recovery posture, secure configuration, workflow state and approved signing-asset presence. It prints no account identities, connection details, keys or asset bytes, and writes nothing. Missing records are not repaired. `release_authorized` is always false because the command cannot certify acceptance. Original `check_owner_readiness` remains unchanged.

Operational UI removes local synthetic-only banners. A new immutable `Document.is_specimen` issuance snapshot defaults to true, including all preexisting rows via additive migration 0015. Only newly issued operational editions receive false. HTML, newly rendered PDFs and operational public lookup consult that provenance, not the current mode; historical specimens are not returned by operational verification. Official credentials omit specimen labels; previews, explicit proofs and all participation design proofs remain marked. Operational PDF template metadata has a distinct suffix. Existing encrypted artifacts remain immutable and are not silently relabeled; a formal replacement is needed for a previously issued specimen, including generation in another language. Artwork, layout, membership policies and signing/photo prerequisites are unchanged.

Public operational forms do not treat Render REMOTE_ADDR as a client identity. They use deliberate whole-service fixed-window ceilings: 200 authentication attempts per five minutes (plus ten per hashed normalized account), 300 verifications per ten minutes and 50 partnership attempts per ten minutes. The global authentication bucket is locked and checked before any account bucket can be created; exhausted global attempts do not grow per-account rows. Account identity uses NFKC normalization before case folding, matching canonical username forms. Forwarding headers and changing ingress peers cannot split these ceilings. These are conservative configured controls, not measured load capacity or DDoS immunity; exhaustion of a service ceiling is an explicit availability tradeoff. Local synthetic per-peer limits and the existing administrative ceiling are unchanged.

Migration 0016 adds indexed creation time to rate buckets, initializing legacy rows conservatively at migration time. Operational attempts prune up to 1000 counters older than one hour, before taking current-window locks; PostgreSQL cleanup skips locked rows. Active five/ten-minute limits are retained. No scheduled worker or paid resource is needed, and no growth continues when there is no traffic. Application/renewal guards no longer block ordinary profile correction outside preview modes; signup/application/renewal still obey their switch, and previews still deny profile writes.

Both additive fields retain database defaults (specimen true, counter creation time now), so an old worker can still insert records during zero-downtime cutover. Regressions exercise the historical pre-0015 Document ORM and a legacy key/count-only counter insert against the new schema.

## Eventual rollout and rollback

No active Render setting is changed in this increment. After remaining acceptance evidence, deploy the exact reviewed version privately first, inspect sanitized readiness output and backup, then apply the distinct operational decision with only the independently authorized workflows enabled. Test AR/FR/EN public pages, primary/delegate/member sessions, account ownership isolation, signup/application, manual finance approval, issuance/PDF and QR/reference verification, invalid/revoked documents, foreign-origin CSRF and revoked delegation denial. Use controlled test identities, not another person's real records.

Close a workflow by setting its switch to `0`. Restore private access by setting `ANTHEEC_MODE=owner-testing` and all three switches to `0`, then redeploying the compatible reviewed code. This changes access, not data: never restore an old backup over the live DB as an access rollback, delete migrations, replace the encryption key or remove audit history. No paid resource/plan/network opening, DNS, external delivery or Tighri change is authorized by this code.
