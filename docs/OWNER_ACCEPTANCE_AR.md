## المسار الثاني: القبول الوظيفي الكامل في بيئة اصطناعية معزولة

**لا تنفذ الجدول التالي على خدمة التجربة الحالية**: التسجيل والمدفوعات والإصدار والتحقق وتنزيل الوثائق محجوبة عمدًا. لا تعطّل middleware ولا تغيّر وضع الإنتاج لتمرير الاختبار. يجهز المهندس أولًا نسخة محلية على loopback وقاعدة اصطناعية مستقلة، أو مقترح استضافة معزولة بتكلفته قبل أي شراء. لا تستنسخ أسرار أو بيانات الاستضافة إلى نسخة التطوير. لا تعرض إعدادات `test` أو `dev` على الإنترنت.

قبل التنفيذ، سجل عنوان الهدف ونسخة المصدر ونوع القاعدة، وتحقق من عدم وجود أسرار أو صلات بـTighri، ومن عدم وجود بريد خارجي أو وسيلة دفع حقيقية. استخدم أسماء Synthetic وعناوين `example.invalid` وصورة هندسية اصطناعية وتوقيعًا/طابعًا اختباريين واضحين؛ لا تستعمل هوية أو توقيعًا حقيقيًا. يزود المهندس المالك بروابط السجلات الاصطناعية من تلك البيئة فقط. الحالات التالية **لم تنفذ يدويًا**؛ التغطية المذكورة آلية في قاعدة اختبارات منفصلة.

## إعادة تشغيل الأدلة الآلية

على نسخة تطوير محلية مستقلة فقط، بعد تثبيت `requirements.txt`، شغل المجموعة الكاملة (ليست تعليمات Render Shell):

```sh
ANTHEEC_MODE=development ANTHEEC_DB_ENGINE=sqlite python manage.py test content governance --settings=antheec_app.settings.test
python tools/validate_baseline.py
python -m unittest discover -s tests -v
```

SQLite يتخطى اختبارات قفل PostgreSQL؛ CI على PostgreSQL 16 هو مرجعها. النسخة الآلية تنشئ قاعدة اختبار ولا تملأ قاعدة الاستضافة، ولا تولد حسابًا للمالك على الموقع. الاختبارات لا تثبت جودة الطباعة المادية أو الاستعادة الفعلية أو التحمل عند 512 MiB.
