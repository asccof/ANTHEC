# ANTHEEC current domain contracts

Version 1.0, 2026-10-10. Institutional rules are APPROVED_POLICIES.md (SRC-08). Engineering details below implement those rules and are identified as technical choices. Earlier contract versions in Git history were proposals and are superseded wherever inconsistent. Original acceptance AC-01–14/T01–12 remains tracked; service tests alone do not establish complete platform acceptance.

## Aggregates and invariants

Authority has a database-enforced singleton primary user. Delegations grant operational authority with an epoch; only the primary changes them. The middleware checks live delegation on every administrative request, so revocation rejects even previously MFA-verified sessions. Delegates never become Django superusers and cannot access user/group management. No generic business CRUD or primary-replacement endpoint is exposed. Database/host operators remain privileged outside this application boundary.

Price is append-only by service, with timezone-aware effective timestamp and amount. Quote fixing snapshots the active price; annual renewal fixes a new quote independently. Changes do not alter accepted funds or current terms. Initial approved current prices are seeded once; no synthetic campaign end. Cash/transfer verification retains proof reference and immutable receipt identity; full exemption/refund decisions retain the original payment. Amounts are finite MAD values with two decimal places.

Application precedes Membership. Membership approval requires verified applicable funds or a reasoned exemption; founders/honorary are free but still require approval. One transaction records approval, membership, documents/outbox and command result. Third-tier approval/renewal additionally creates linked professional accreditation and an independent certificate in that same transaction. A lower tier never grants automatic accreditation. Independent individual/institution/course accreditation is a separate administrative decision; assessment files/fees have no public API in this increment.

Technical calendar rule: dates in Africa/Casablanca, valid interval [starts_on, ends_on); annual end is corresponding calendar date next year, with February 29 clamped to February 28. Early renewal begins at current exclusive end; late renewal at new approval day. No gap is backdated. Future renewed documents have a pending-before-start state rather than incorrectly asserting current validity. Founder/honorary ends_on is null. Dates and policy version are preserved in history; receipts do not recalculate.

Administrative sensitive service commands lock the singleton authority before permission checks and mutations, serializing this bounded prototype's sensitive decisions. This is a deliberately simple correctness tradeoff, not a production scaling guarantee. Command uniqueness is (actor, action, key); canonical input digest rejects payload changes on replay. Rights, documents and render outbox commit atomically. Retry preserves origin/serial; encrypted printable rendering is idempotent. External email/delivery and exactly-once external delivery are not implemented or claimed.

Document has exactly one typed origin, unique random serial, unique QR token digest, extra printed code digest, encrypted credential material, version, holder-name snapshot and optional one-to-one predecessor. Replacement invalidates the previous document in the same transaction; suspension/cancellation/reactivation is derived from current origin without validity caching. A linked accreditation cannot appear active while membership is inactive. Membership state changes synchronize its linked certificate; renewed terms must keep their approved date periods.

## Permission and security contracts

A primary or active operational delegate may decide membership/accreditation, verify funds, edit prices, manage activity admission/attendance and make reasoned exemptions/refunds/reissues. Only the primary appoints/removes directors. A CMS-only account is not an operational director. Business actions require verified MFA session, current delegation epoch and password+factor reauthentication within a five-minute technical window. Recovery uses password plus hashed one-use emergency code; failed account challenges are rate limited and logged without credentials. TOTP enrollment requires password and successful authenticator token; confirmed devices cannot be reset through ordinary enrollment. No second administrative approval is imposed.

Public/member document downloads enforce holder/guardian ownership or administrative permission. All administrative writes and participant submissions require CSRF. Production settings remain deliberately disabled. Private attachments/upload scanning, protected backups/restoration and complete security acceptance remain separate work; no real files are accepted by this core.

## Registration and consent

Authenticated adult participant profile links to one account. A minor profile is controlled by its authenticated guardian; each registration stores explicit guardian name/capacity, consent timestamp, the activity's consent text and version. No invitation before administrative confirmation. Unique (activity, participant) prevents repeated registration of the same managed profile; account/guardian-managed stable profile references avoid collecting national IDs or birth dates merely for deduplication. Identity matching across different accounts is not established by this technical prototype and requires readiness verification; name alone is never treated as globally unique.

Capacity is checked under the sensitive-command lock and activity lock. Confirmed invitations can be cancelled; cancellation releases the counted seat. Attendance is unique per registration and requires a valid confirmed invitation within the activity dates and administrative MFA authorization; future invitations report pending, and past invitations expired; public verification cannot record attendance. Event age conditions remain configurable administration data, not fixed organizational policy.

## Public verification and rendering

QR links to the configured local development origin with token in URL fragment. Browser moves it into a CSRF-protected POST and removes the fragment, keeping credentials out of HTTP URL/access logs. Alternate verification is reference plus printed code; reference alone and name search reveal nothing. Same invalid response for missing/wrong credentials; hashed IP/time buckets limit guessing. Verification response is allowlisted to name/type/reference/dates/current status. No contact/address/identity/internal reasons/fees/criteria. Prior notice acknowledgment is required before person-based issuance/registration. Optional directory consent has no effect on validity and remains separate from verification.

Printable gold card, membership card, professional/independent accreditation certificate and personal invitation are separate HTML artifacts with individual QR/reference/code; authorized holder/admin download only. These are development printing artifacts, not approved production graphic templates or digitally signed PDFs. Rendered HTML and credential material are encrypted using an explicit data key; no key is committed except a clearly synthetic test fixture. Delivery adapters remain offline.

## Privacy, records and launch gates

Minimal core person fields are name, account/contact, minor/guardian association, verification notice and optional directory consent. No CIN, birth date, address, photo or clinical file. Decision/audit/payment/quote/term/consent/document history is retained by service; no ordinary update/delete endpoints exist. This does not prevent a privileged database operator from editing records. Automatic deletion is intentionally not enabled until legal retention, archive/holds, backup and rights-handling procedures are reviewed. Rate-limit buckets are operational metadata and need bounded cleanup before production.

APPROVED_POLICIES.md and POLICY_EXECUTION.md distinguish approved organizational rules, tested services and incomplete UI/legal/security acceptance. No contract or successful test authorizes launch, real-person records, paid providers or external delivery.
